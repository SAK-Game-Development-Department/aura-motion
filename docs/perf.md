# 性能の測定（perf）

## 目標
| 項目 | 目標 | 測り方 |
|---|---|---|
| 描画 | 60fps（フレーム時間 p95 ≤ 25ms） | D キーの `fps` / `frame ema` / `p95`、または `?bench=1` |
| トラッキング | 30fps 以上 | D キーの `source` 行（`worker/GPU NNfps`） |
| 遅延（計測できる部分） | 撮影→推論→表示の合計 ≤ 90ms | D キーの `capture→tracked` + `tracked→display` |
| 長時間稼働 | 8時間でメモリが増えない | `npm run soak`（短縮版）＋会場での2時間テスト（venue-checklist A7） |

## 測定ツール
- **`?bench=1`**: 粒子数を 3万 → 6万 → 10万 → 15万 → 25万 → 40万（WebGL2 は10万まで）と6秒ずつ変え、
  フレーム時間の平均と p95、トラッキングの fps・推論時間を記録する。結果はコンソールの表と JSON ファイル（ダウンロード）に出る。
  - **トラッキングあり**: そのまま `/?bench=1`（カメラの前に人が立った状態で測る）
  - **トラッキングなし**（描画だけの負荷）: `/?bench=1&source=synth`
  - 2つの差が「トラッキングと描画が GPU を取り合う」コストになる
- **D キーのデバッグ表示**: CPU のフレーム内訳（input / logic / world / submit）と、トラッキングの推論・輪郭抽出・場の計算の時間
- **自動の品質調整**: フレーム時間の EMA が 18.5ms を 1.5秒超えると、粒子数 → 解像度 → エフェクトの順に1段ずつ落とす。
  13ms を 8秒下回ると戻す（`src/config/render.ts` の `QUALITY`）

## 測定結果

### 開発環境（参考値。ヘッドレス Chromium 156 + SwiftShader = GPU を CPU でエミュレート）
実機の GPU とはまったく比較にならないので、**相対的な傾向**だけを見るための値です。

`?bench=1&source=synth`（トラッキングなし、640×360、2026-10-22）:

| 粒子数 | フレーム平均 (ms) | p95 (ms) | fps |
|---|---|---|---|
| 30,000 | 580 | 917 | 1.7 |
| 60,000 | 922 | 1,050 | 1.1 |
| 100,000 | 1,323 | 1,667 | 0.8 |
| 150,000 | 2,012 | 2,233 | 0.5 |
| 250,000 | 2,717 | 3,783 | 0.4 |
| 400,000 | 4,417 | 4,533 | 0.2 |

- 粒子なし（`flags=-particles`）だと 17〜29fps 出る（640×360）。**コストのほとんどは粒子の compute と描画**で、粒子数にほぼ比例する。
  品質の自動調整が粒子数から先に落とすのは、この傾向に合っている
- トラッキング（偽カメラ、worker/GPU）: 姿勢推定 約400ms、輪郭抽出 約80〜120ms、場の計算 約2〜3ms／フレーム（SwiftShader）。
  場の計算（CPU）は推論に比べて無視できる大きさ
- 実機の GPU では桁が2つ以上違う。目標の判定には使わず、展示 PC での `?bench=1` の結果を下の表に記入すること

## 負荷の内訳と設計上の対策
| 負荷 | どこで | 対策 |
|---|---|---|
| 姿勢推定（Pose Landmarker lite） | Worker 内の GPU（WebGL） | `TRACKING.poseModel = 'lite'`。余裕があれば `full` |
| 輪郭抽出（Selfie Segmenter） | Worker 内の GPU。入力は 192×108 に縮小 | 縮小してから推論するので読み戻しが小さい。重いときは1フレームおき（`segmentHalfRate`） |
| シルエット場（距離変換・速度場） | Worker 内の CPU（約1〜3ms） | GPU を使わない（docs/decisions.md D4） |
| 粒子の更新 | 描画側の GPU（compute） | 粒子数を品質調整で増減する |
| ブルーム | 描画側の GPU | 品質調整の最後の段で切る |
| フレームの受け渡し | メインスレッド（createImageBitmap 640px） | 推論中は新しいフレームを送らない（古いフレームを溜めない） |

## 長時間稼働（ソーク）
`SOAK_MINUTES=30 npm run soak` は、ボットに連続でプレイさせながら（fast モードで約30秒に1人）、30秒ごとに JS ヒープ、DOM ノード数、
GPU 資源の数（ジオメトリ、テクスチャ、レンダーターゲット）を `soak-out/*.csv` に記録します。
後半の平均が前半より 15% 以上増えたら失敗にします。
