# 実機でしか確認できない項目（術バトル版）

開発環境（カメラなし、ヘッドレスの SwiftShader）では確認できない項目です。展示 PC と本番のカメラ・照明で確認し、「結果」欄に書き込んでください。
計測値はアプリの **D キー**（デバッグ表示）と、**ジェスチャーラボ**（`npm run lab` または https://aura-lab-csq.pages.dev）で読めます。

## P1（いま）: 手の認識の実現性 ── ここが確定するまで P2 に進みません
| # | 項目 | 手順 | 合格基準 | 結果 |
|---|---|---|---|---|
| R1 | 手が見つかる | ラボを開き、入力を「カメラ」にして、手をカメラに向ける | 21点が手に重なる。`tracking` が 25fps 以上 | |
| R2 | 8形の認識 | 各形を作り、手をゆっくり回す（±30°）・近づける・遠ざける。信頼度のバーと「構え」を見る | 各形で迷わず構えが出る。別の形に跳ばない | |
| R3 | 混同行列（1人） | 8形と「なし」を各 60 フレーム記録 →「規則ベースで評価」 | 再現率 95% 以上、別の形への誤認識 3% 以下 | |
| R4 | 混同行列（複数人） | 記録者タグを変えて、手の大きさの違う 3人以上で R3 | 同上。特定の人だけ悪くならない（悪ければ自動校正の後で再評価） | |
| R5 | 規則 vs kNN | R4 のデータで「kNN で評価」（人ごとの交差検証） | どちらが良いかを記録する（P2 でどちらを使うか決める） | |
| R6 | 不安定な形の特定 | R3〜R4 の混同行列で、誤認識の多い組を書き出す | つの・たてる・かぎ・つまむ のうち不安定なものを外して 6形に絞るか判断する | |
| R7 | 自然な手の誤発動 | アプリの練習画面で、30秒間、話すときのように手を動かす（技を出すつもりはない） | 技の発動が 1回以下 | |
| R8 | 動き | はらう（左右上下）・おす・ひく・はじく を各10回 | 8回以上で正しく発動する。戻りの動作で逆の技が出ない | |
| R9 | 空中の印 | さす（人差し指）で まる・さんかく・いなずま・うず を各10回描き、止める | 8回以上で正しく認識される | |
| R10 | 両手 | 両手を近づけてから、ぱっと離す | 10回中9回発動。片手の動きでは発動しない | |
| R11 | 反応の速さ | 形を作った瞬間から手の上のアイコンが灯るまでを、スマホのスロー撮影（240fps）で数える | 120ms 以内（D キーの `capture→tracked`＋`tracked→display` も記録） | |
| R12 | 照明 | 部屋を暗くする、逆光にする | 暗いと警告が出て、3形モードに切り替わる。3形は認識できる | |
| R13 | 多様性 | 手袋（薄手）、ネイル、子どもの手、肌の色の違う手 | 自動校正の後で R2 が成り立つ | |
| R14 | 背景の手 | 後ろに別の人が手を出す | プレイヤーの手（大きい方）を優先し、後ろの小さな手を無視する（`ignoredHands`） | |

## 性能（展示PC）
| # | 項目 | 手順 | 合格基準 | 結果 |
|---|---|---|---|---|
| A1 | 描画 | アプリで1分遊び、D キーの `fps`・`p95` を見る | 55fps 以上、p95 25ms 以下 | |
| A2 | トラッキング | `source` 行の `worker/GPU NNfps` | 30fps（カメラが 30fps なら 28 以上） | |
| A3 | 経路 | `tracking` 行と `attempts` | `worker/GPU`（違えば docs/decisions.md D3 に機種を追記） | |
| A4 | 負荷の測定 | `/?bench=1`（手を出した状態）と `/?bench=1&source=synth` の JSON を docs/bench/ に保存 | docs/perf.md に要約する | |
| A5 | 長時間 | 2時間、無人のデモ＋10分ごとに1回遊ぶ | fps の低下が 10% 以内、heap の増加が 10% 以内 | |
